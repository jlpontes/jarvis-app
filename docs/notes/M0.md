# M0: o esqueleto, em 5 ideias

O M0 não tem regra de negócio nenhuma. Ele monta o "encanamento": uma API que responde, uma tela
que consome essa API, comandos para rodar e checar tudo, e um CI que repete esses checks a cada push.

## 1. `uv` + `pyproject.toml` + `uv.lock` ↔ `vcpkg.json` + `builtin-baseline`

No C++, o `vcpkg.json` lista as bibliotecas (nlohmann-json, catch2, sqlitecpp) e o `builtin-baseline`
fixa as versões. Aqui, o `server/pyproject.toml` lista as dependências e o `uv.lock` fixa a versão
exata de cada uma, inclusive das indiretas. O `uv` também baixa o Python certo (3.15, conforme
`server/.python-version`), então ninguém depende do Python do sistema. `uv run <comando>` roda o
comando dentro desse ambiente, como o preset do CMake garante que todos compilam igual.
No web, `package.json` + `package-lock.json` fazem o mesmo papel.

## 2. `Makefile` ↔ `CMakePresets.json`

No C++, você digita `cmake --preset debug` e `ctest --preset debug` em vez de lembrar flags.
Aqui o `Makefile` faz o mesmo papel para os dois lados ao mesmo tempo: `make dev`, `make test`,
`make lint`. `make help` mostra a lista. O CI roda exatamente esses comandos, então
"passou na minha máquina" e "passou no CI" significam a mesma coisa.

## 3. A configuração vem do ambiente: `Settings` ↔ `std::getenv("HOME")` em `apps/cli/main.cpp`

No C++, o CLI monta `~/.jarvis` à mão com `getenv`. Aqui, `server/src/jarvis/core/config.py`
declara uma classe `Settings` (pydantic-settings). Cada campo vira a variável `JARVIS_<CAMPO>`
lida do ambiente ou do `.env`, **já validada e com o tipo certo**: `JARVIS_ENV=staging` é
recusado, e `~` vira a sua pasta home. Segredos (senha, token) vão entrar aqui no M1, e só no `.env`.

## 4. Tipos gerados, não escritos: OpenAPI → `schema.d.ts` ↔ `to_json` escrito à mão

No C++, `task.hpp` tem um `to_json` escrito à mão para cada struct. Se você esquecer um campo, o
JSON sai sem ele. Aqui, o modelo Pydantic `Health` (em `api/app.py`) é a única definição:

```
Pydantic (Python) ──FastAPI──▶ OpenAPI (JSON) ──openapi-typescript──▶ schema.d.ts (TypeScript)
```

`make types` refaz essa corrente, e o CI falha se o `schema.d.ts` commitado estiver velho. Se a API
mudar e o front não acompanhar, o `tsc` acusa. É a ideia central do plano: declarar cada coisa
uma vez só. Detalhe: o gerador roda com o próprio TypeScript 5, em `web/tools/openapi/`
(veja `docs/decisions/0002`).

## 5. Duas portas em dev, uma em produção

- **`make dev`**: o Vite (:5173) serve o React com recarga instantânea e repassa (*proxy*) tudo
  que começa com `/api` para o uvicorn (:8000). O navegador acha que fala com um servidor só.
- **`make start`**: o Vite compila o React em arquivos estáticos (`web/dist`), e o próprio FastAPI
  os serve (`app.frontend(...)`, recurso novo da FastAPI) na mesma porta da API. Uma navegação para
  `/tarefas` recebe o `index.html`, e o React decide a tela. É assim que vai rodar no Docker (M3).

As rotas da API sempre ganham dos arquivos do front, e qualquer `/api/...` desconhecido responde
404 em JSON, nunca HTML.
